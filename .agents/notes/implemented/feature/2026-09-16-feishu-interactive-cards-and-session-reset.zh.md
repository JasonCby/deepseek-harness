# Agent Note: 飞书交互卡片与聊天会话重置

Status: implemented

[English](2026-09-16-feishu-interactive-cards-and-session-reset.md) | 中文

## Problem

飞书前置入口此前只能发文本与上传文件，于是一轮里真正有用的输出若是某种渲染结构——状态看板、指标表格、简短报告——就只能用散文描述或交出一个文件。另一方面，一个聊天映射到一个永不结束的 Session（见[飞书机器人 Agent Note](../architecture/2026-09-08-feishu-bot-plugin.zh.md)），因此换话题的用户会把此前每一轮都带进新话题的提示词。Web UI 可以为同一工作区打开全新会话，但聊天侧用户没有对应手段：想重新开始只能删掉持久日志，而那会摧毁 Web UI 仍可打开的历史。

## Decision

`feishu_deliver` 在文件之外承载交互卡片，三条聊天命令把单个聊天推进到新的会话代际。二者都作用于持久会话日志与活动传输边，因此都不新增服务、包或 agent-loop 扩展点。

### 交互卡片

工具在 `paths` 之外接受可选的 `cards` 数组，`paths` 不再是必填项，于是一轮可以只声明卡片、只声明文件，或两者兼有。卡片被接受的条件是：它是普通对象且 `elements` 属性为数组；飞书卡片 schema 的其余部分归飞书判定，因为工具的职责是拒绝根本不可能成为卡片的模型输出，而不是重新实现一套第三方 schema。结算读取持久的 `tool/call` 参数，保持声明顺序，并按序列化 JSON 去掉完全重复项。路由器在已结算轮次中先发卡片再发文件，每张卡片经活动边的 API client 以一条 `msg_type: 'interactive'` 回复发出；单张卡片失败只记日志，不阻止其余卡片与文件。每轮 20 条的上限对卡片与文件分别生效。

### 聊天会话重置

一条获准消息的文本（去除首尾空白后）恰为 `/new`、`/reset` 或 `/新会话` 时不进入 agent。`ConversationRouter` 弃用该聊天的路由句柄、递增该聊天的代际、持久化代际，并回复固定提示 `已开启新会话，此前的对话上下文已清空。`。被弃用的 agent 继续运行，其持久会话留在磁盘上，因此在 Web UI 中仍被列出且可打开；只有聊天的路由指针前移。下一条普通消息哈希到全新的 Session id，并创建或恢复该会话。

代际持久化在 `$DSH_HOME`（默认 `~/.dsh`）下的 `feishu-router-state.json`。路由器首次使用时加载一次该文件，只接受正整数，并以临时文件加 `rename` 原子替换，因此崩溃或半写文件都不会丢失或损坏一次重置。写入失败只记日志，内存中的代际仍然生效。

### 会话身份

`sessionIdForChat(chatId, epoch = 0)` 哈希 `${chatId}#${epoch}` 而非 `chatId`，于是让重启无需旁路状态即可恢复聊天的确定性映射，同时把同一聊天的不同代际分开。

## Alternatives considered

**在提示词或会话日志中新增卡片内容块。** 被否决：模型可见的新内容类型会为一种只有单一传输渲染的呈现方式牵动 LLM 运行时与每个 provider，而 `feishu_deliver` 已经把模型声明的产物留在持久日志中。

**重置时删除或归档持久会话。** 被否决：Web UI 保持会话可打开，日志是用户所付代价的持久记录；开新话题不应摧毁用户并未要求放弃的历史。

**每次代际随机 id 加旁路映射。** 被否决：确定性哈希让恢复仍是一次 `sessionPersistence.list()` 成员检查，代际文件于是只记录一个计数器，而不是引入可能与日志不一致的第二套身份空间。

**用压缩或"忘记对话"的提示词实现重置。** 被否决：上下文仍留在日志里，其 token 成本会随重放前缀回来，而且效果取决于模型行为。

**由模型调用的重置工具。** 被否决：用户键入的命令确定性地立即生效，而经 agent 转交会把一次上下文重置变成一轮模型消耗，还允许模型拒绝执行。

## Consequences

- 每个聊天的 Session id 都变了，因为 `sha256(chatId#0)` 不同于此前的 `sha256(chatId)`。已有聊天在此变更后不会恢复其先前会话；那份日志留在磁盘上且可打开，聊天在新代际中继续。
- 每个已结算轮次的投递顺序是：文本回复、卡片、文件。
- 什么都不声明的调用是 schema 合法的，因此空交付以零计数队列作答；工具结果分别报告文件与卡片计数，模型由此能看出自己什么都没声明。
- `elements` 数组之外的卡片合法性由飞书执行：此类卡片在 API 处失败、被记入日志并跳过，其余投递照常进行。
- 代际状态位于会话日志之外，因此重置要在重启后仍然生效，`$DSH_HOME` 必须可写且持久；文件丢失会把聊天回退到代际 0，并恢复该聊天最早持久化的会话。
- 被弃用的 agent 保持注册而非被 dispose，因此一次重置会保留一个空闲 agent 及其会话常驻，直到注册表将其释放。

## Testing

`packages/feishu/feishu/tests/T01-conversation-router.spec.ts` 固定卡片先于文件的顺序、拒绝没有 `elements` 数组的载荷，以及在隔离 `DSH_HOME` 下重置命令的会话迁移；`packages/feishu/feishu/tests/T02-transport-edges.spec.ts` 固定卡片发送器在两条传输边上的接线。
